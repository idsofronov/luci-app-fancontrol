# luci-app-fancontrol

[简体中文](README.zh.md) | **Русский** | [English](README.en.md)

Простое управление вентилятором через LuCI для GL.iNet GL-MT3600BE / Beryl 7 под управлением
ImmortalWrt или прошивки в стиле OpenWrt с пакетной системой `apk`.

После установки пакет добавляет в LuCI раздел **Система > Управление вентилятором**.
Режим по умолчанию — `system`, поэтому управление вентилятором не перехватывается,
пока пользователь не выберет автоматическое или фиксированное управление.

## Скриншоты

Скриншоты с GL.iNet GL-MT3600BE / Beryl 7 под управлением ImmortalWrt 25.12
с темой Argon.

## Возможности

- Страница LuCI в разделе **Система > Управление вентилятором**.
- Отображение температуры CPU, Wi-Fi и Ethernet, текущих оборотов вентилятора,
  мощности вентилятора и расчётной скорости вентилятора в процентах.
- В качестве температуры для управления используется максимальное корректное значение
  с ключевых датчиков, поэтому перегретые Wi-Fi-чипы не остаются без внимания из-за
  более низкой температуры CPU.
- Поддерживается рекомендуемая кривая и пользовательские температурные точки.
- В пользовательском режиме можно изменять только температурные точки. Значения PWM,
  пути sysfs и уровни мощности вентилятора остаются защищёнными.
- Фиксированный режим мощности вентилятора предназначен только для кратковременной диагностики.
- Демон, управляемый через procd, и лёгкий watchdog.
- По умолчанию используется минимальное количество записей в журнал.

## Совместимость

### Проверенное устройство

| Параметр | Значение |
| --- | --- |
| Устройство | GL.iNet GL-MT3600BE / Beryl 7 |
| Семейство прошивок | ImmortalWrt 25.12 / система в стиле OpenWrt |
| Целевая платформа | mediatek / filogic |
| Менеджер пакетов | `apk` |
| Драйвер вентилятора ядра | `pwm-fan` |

Ожидаемые узлы sysfs:

- Температура CPU: `/sys/class/hwmon/*/name = cpu_thermal` или
  `/sys/class/thermal/thermal_zone0/temp`
- Драйвер вентилятора: `/sys/class/hwmon/*/name = pwmfan`
- Обороты вентилятора: `fan1_input`
- Управление PWM: `pwm1`

Другие устройства OpenWrt / ImmortalWrt с вентилятором также могут работать,
если они предоставляют стандартную структуру sysfs для `pwm-fan`. На непроверенных
устройствах используйте пакет с осторожностью.

### Быстрая проверка совместимости

Выполните следующие команды на роутере:

```sh
for d in /sys/class/hwmon/hwmon*; do
  echo "$d: $(cat "$d/name" 2>/dev/null)"
  ls "$d"/fan*_input "$d"/pwm* 2>/dev/null
done

for z in /sys/class/thermal/thermal_zone*; do
  echo "$z: $(cat "$z/type" 2>/dev/null) $(cat "$z/temp" 2>/dev/null)"
done
```

Если вы не можете найти `pwmfan`, `fan1_input` и `pwm1`, считайте устройство
несовместимым.

## Установка

### Установка одной командой

Выполните одну из следующих команд по SSH на роутере:

```sh
wget -O- https://raw.githubusercontent.com/idsofronov/luci-app-fancontrol/main/install.sh | sh
```

```sh
curl -fsSL https://raw.githubusercontent.com/idsofronov/luci-app-fancontrol/main/install.sh | sh
```

Более безопасный вариант установки вручную:

```sh
wget -O /tmp/install-fancontrol.sh https://raw.githubusercontent.com/idsofronov/luci-app-fancontrol/main/install.sh
sh /tmp/install-fancontrol.sh
```

`install.sh` — удобный способ установить пакет непосредственно из исходников.
Он не отслеживается базой пакетов `apk`, поэтому после обновления прошивки или
восстановления системы его может потребоваться установить заново. Для длительного
использования с чистой установкой предпочтительнее `.apk` из раздела Releases,
если он доступен, с установкой через `apk add ./package.apk`.

Скрипт установки не изменяет источники пакетов, не выполняет `apk upgrade`,
не перезагружает роутер и не перезаписывает существующий `/etc/config/fancontrol`.
Заменяемые файлы пакета сохраняются в резервной копии в `/tmp`.

### APK из Releases

В репозитории настроена автоматическая сборка через GitHub Actions. Каждый push в `main`
собирает стандартный пакет `.apk` с использованием SDK ImmortalWrt 25.12 для
`mediatek/filogic` и загружает его в предварительный релиз `continuous`. В будущем
теги `v*` будут создавать фиксированные версии релизов.

Если вы предпочитаете установку, отслеживаемую базой пакетов `apk`, скачайте `.apk`
из Releases или установите сборку, автоматически отслеживающую ветку, непосредственно
на роутере:

```sh
wget -O /tmp/luci-app-fancontrol.apk https://github.com/idsofronov/luci-app-fancontrol/releases/download/continuous/luci-app-fancontrol_latest_all.apk
apk add /tmp/luci-app-fancontrol.apk
```

APK больше не имеет жёсткой зависимости от пакета `kmod-hwmon-pwmfan`. Роутер уже должен
предоставлять драйвер `pwm-fan`: он может быть встроен в ядро или установлен отдельно,
а также должны существовать ожидаемые узлы sysfs `pwmfan`, `fan1_input` и `pwm1`.
Если эти узлы отсутствуют, пакет может установиться, но управлять вентилятором не сможет.

Сборка из ветки `main` всегда содержит последние изменения и лучше всего подходит
для раннего тестирования. Для длительного стабильного использования предпочтительнее
версионированный Release, когда он доступен.

### Сборка через SDK

Поместите этот пакет в feed или дерево пакетов OpenWrt / ImmortalWrt,
а затем соберите его стандартным способом через SDK.

```sh
make package/luci-app-fancontrol/compile V=s
```

Пакет помечен как `PKGARCH:=all`.

## Использование

1. Откройте LuCI и перейдите в **Система > Управление вентилятором**.
2. Режим по умолчанию — **Системный по умолчанию**. Плагин не управляет вентилятором.
3. Выберите **Автоматическое управление температурой**, затем:
   - **Рекомендуемая кривая**: хороший вариант по умолчанию для большинства GL-MT3600BE.
   - **Пользовательская температура**: изменяйте только температурные точки;
     уровни мощности вентилятора остаются защищёнными.
4. Нажмите **Сохранить и применить**.
5. На странице отображаются температура управления, источник самого горячего датчика,
   состояние вентилятора, обороты и текущая причина выбранного состояния.

Фиксированная мощность вентилятора предназначена для кратковременной диагностики,
например для проверки вращения вентилятора или оценки шума на определённом уровне.
Для длительной работы рекомендуется автоматический режим.

## Стратегия работы вентилятора по умолчанию

Рекомендуемая автоматическая кривая:

| Температура | Состояние вентилятора |
| --- | --- |
| `< 60°C` | остановлен |
| `>= 65°C` | низкая скорость, 50% |
| `>= 72°C` | средняя скорость, 70% |
| `>= 79°C` | высокая скорость, 85% |
| `>= 86°C` | защита на полной скорости, 100% |

В пользовательском режиме можно изменять только следующие пять температурных точек:

- Температура остановки: `45-70°C`
- Начало низкой скорости: `55-78°C`
- Начало средней скорости: `60-84°C`
- Начало высокой скорости: `68-88°C`
- Защита на полной скорости: `80-90°C`

Правило: `stop < low < medium < high < full`, между соседними точками должно быть
не менее `3°C`.

## Рекомендации по температуре

| Предпочтение | Остановка | Низкая | Средняя | Высокая | Полная защита |
| --- | --- | --- | --- | --- | --- |
| В приоритете тишина | 62°C | 68°C | 75°C | 82°C | 88°C |
| Сбалансированный режим | 60°C | 65°C | 72°C | 79°C | 86°C |
| В приоритете охлаждение | 58°C | 63°C | 70°C | 77°C | 84°C |

Пороговые значения для снижения скорости рассчитываются автоматически. Например,
порог между низкой и средней скоростью — это целая часть среднего значения,
поэтому демон никогда не использует неоднозначные дробные пороги вроде `74.5°C`.

## Защитное поведение

- Температура управления — максимальное корректное значение среди CPU, Wi-Fi 0,
  Wi-Fi 1, Ethernet и других известных ключевых датчиков.
- Показания температуры должны быть корректными числами в диапазоне `0-150°C`;
  некорректные значения запускают защиту на полной скорости.
- Температура сглаживается по последним 3 измерениям.
- При запуске вентилятор на 1 секунду включается на 100%, затем переходит на целевой уровень.
- Проверка оборотов при запуске откладывается на 9 секунд.
- Запуск на низкой скорости, остановка и снижение скорости выполняются только после
  стабилизации температуры.
- После запуска вентилятор должен работать не менее 90 секунд, прежде чем остановиться.

## Полезные команды

```sh
/usr/bin/fancontrol status
/usr/bin/fancontrol apply
/usr/bin/fancontrol system
/etc/init.d/fancontrol restart
logread -e fancontrol
```

Восстановить системное управление вентилятором по умолчанию:

```sh
/usr/bin/fancontrol system
```

Временно включить отладочное логирование:

```sh
touch /tmp/fancontrol.debug
rm -f /tmp/fancontrol.debug
```

## Примечания по безопасности

- Режим по умолчанию — `system`; пакет не перехватывает управление вентилятором,
  пока не выбран автоматический или фиксированный режим.
- Фиксированный режим предназначен только для кратковременного тестирования.
- Управление вентилятором обращается к аппаратным узлам sysfs. Перед использованием
  на устройствах, отличных от GL-MT3600BE, проверьте совместимость.
- Автор и участники проекта не несут ответственности за повреждение оборудования,
  вызванное неправильной прошивкой, несовместимым оборудованием или небезопасными
  ручными изменениями.
